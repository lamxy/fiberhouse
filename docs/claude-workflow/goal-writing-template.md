# /goal 寫作範本

`/goal` 其實是一個在當前會話內生效的 prompt-based Stop hook：每輪結束後，Claude Code 把 goal 條件和目前為止的整段對話交給小型快速模型（預設 Haiku 級）判定。檢查器看得到之前說過的限制（例如「暫不推送」），但會以 goal 文字為準來判斷。它不會自己執行命令或讀檔，只能根據對話裡已經呈現的內容判斷。官方建議把「必須遵守的限制」直接寫進條件（見 <https://code.claude.com/docs/en/goal.md> 的 "Write an effective condition"）。

## 三個要點

1. **寫明排除項**：不推送、不打 tag、不發布、不改動外部服務。
2. **限定執行範圍**：「按建議執行」改成「按建議執行本機可回滾的改動」。
3. **補充說明寫成驗收標準**：「先保存備用」改成「以文件存檔即算達標」；本 repo 做不到的項目改成「評估並記錄即算達標」。

## 範本

```text
1. <要完成的主要工作>
2. 驗證 <驗證方式>，達到 <預期效果>；評估後按建議執行本機可回滾的改動，每項單獨 commit。
排除：不推送、不打 tag、不發布。
驗收：<方案 X> 以文件存檔即算達標；不在本 repo 的項目評估並記錄即算達標。
接下來無人值守。
```

## 反例（2026-10-26）

```text
2. 同樣要完成驗證，驗證達到效果，進行評估後按最佳建議執行（單獨留底、後面方便我看，且方便單獨回滾）。接下來無人值守。補充：關於應用端的方案先保存下來備用。
```

- 「按最佳建議執行」沒有排除推送。檢查器要求推送 main 並打 tag，但這和之前的「暫不推送」衝突。
- 「先保存下來備用」寫在補充裡，檢查器仍把「方案沒有套用到應用」判為未完成。
- 前端那一項不在本 repo，條件也沒說明怎樣算完成。

結果：檢查器連續 9 次判定未達標，最後由 Claude Code 的阻擋上限強制結束這一輪。
